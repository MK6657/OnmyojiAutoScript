# OAS 控制中心 · 使用说明

> 面向日常使用者 · 基于 UI-claude / Bridge v1.1.3
> 图文版见 `使用说明.html`(含真实界面截图),本文件为纯文本留档版。

---

## 0 · 先弄懂一件事

控制中心不重写阴阳师的自动化逻辑,只是给原来的 OAS 装一个更好用的中文操作台。整套程序分三层:

| 层 | 是什么 | 你要不要管它 |
|---|---|---|
| **OAS Core** | 原项目本体,真正执行任务、控制模拟器(`server.py`,端口 22267) | 必须先启动它,任务才能跑 |
| **Bridge** | 中间适配层,把 Core 接口翻译成界面好用的形式(端口 22367) | 桌面版自动带起;开发模式用脚本启动 |
| **前端(界面)** | 你实际点的操作台(端口 5173 / 4175) | 就是你看到的窗口 |

**记住:控制中心不会替你开游戏、开模拟器。** 游戏窗口得你自己先开好。

---

## 1 · 启动程序

### 最简单 · 双击 `D:\OSAyys\启动.bat`(日常推荐)

一键脚本按 Core → Bridge → 界面 逐层处理:已在跑的**直接复用,绝不重复启动**;端口被陌生程序占用时 Bridge/界面**自动换空闲端口**(Core 端口是全局约定,不自动换,会停下报告占用进程);没在跑的在新窗口拉起并**轮询等就绪**(Core 首启含 OCR 初始化最多等 90 秒;界面首次装依赖可能几分钟)。全部就绪后自动开浏览器。

可选参数(PowerShell 跑 `.\control-center\start.ps1` 时可加):`-SkipCore` 你已自行启动 OAS · `-Prod` 用生产前端(:5173) · `-NoBrowser` 不自动开浏览器 · `-CoreUrl` 指定 Core 地址。

### 方式 A · 桌面版(推荐日常使用)

最省事,双击 portable 程序即可,它会自动带起 Bridge。前提是 OAS Core 已在运行。

```powershell
# 若还没有桌面版,先打一个（build.ps1 现在默认就打 UI-claude 新界面）
cd D:\OSAyys\control-center\desktop
.\build.ps1 -SkipNpmInstall
# 如需对照旧界面：.\build.ps1 -SkipNpmInstall -Ui frontend
# 产物：control-center\desktop\release\OAS-Control-Center-0.1.0-portable.exe
```

### 方式 B · 开发模式(要改界面/调试时)

```powershell
# 1) 先确保 OAS Core 在跑（默认 127.0.0.1:22267）
# 2) 起 Bridge + UI-claude 新界面（start-all 现在转发到智能启动，自动避让端口、复用已在跑的进程）
cd D:\OSAyys
.\control-center\launcher\start-all.ps1
# 打开 http://127.0.0.1:4175/
```

### 方式 C · 试用模式(不想开游戏,只想看界面)

用内置"模拟 Core",不连真实游戏、不碰真实配置、不启动任务。

```powershell
cd D:\OSAyys
.\control-center\launcher\start-dev-stack.ps1
# 一条命令拉起 模拟Core + Bridge + UI-claude
```

> 拿不准三层通没通?跑 `.\control-center\check-wiring.ps1` 逐层只读探测。

## 2 · 界面导览

整个界面是**左边一列账号 + 右边四个视图**。顶部永远显示当前账号和启动/停止按钮。

- **左侧账号栏**:每个账号对应 OAS 一个配置文件,任务/参数/日志相互独立。点头像切换,底部 `＋ 新建账号`。卡片显示状态点和已启用任务数。
- **顶部操作条**:当前账号名、状态、设备;右侧启动/停止/刷新;四个标签(概览/任务/日志/设置)。任务标签有黄色数字=有未保存改动。

---

## 3 · 日常使用流程(7 步)

1. **确认 Core 在线** — 左上"Core 在线"(绿点)才能往下。
2. **选账号** — 左侧点要操作的账号。
3. **去「任务」页配置** — 点任务名*只看配置*,右边开关才是启用。
4. **绑定设备** — 概览「设备」那行点 **「🔗 扫描并绑定窗口」**,选中你的模拟器窗口即可(自动填好窗口句柄和模拟器类型并保存);也可到「运行设置 → 设备」手动填。配错所有任务都会失败。绑定后若仍连不上,多半还要在「运行设置 → 设备」把 `serial` 填成模拟器的 ADB 地址(MuMu12 常见 `127.0.0.1:16384`)。
5. **调参数并保存** — 改过的字段标黄"未保存",确认后点保存(或 Ctrl+S)。只有保存过的才写入 Core。
6. **回「概览」过启动前检查** — 四项全绿启动按钮才可点,有红项点旁边按钮直接跳去修。
7. **点启动,去「日志」看** — 状态变"运行中",日志实时滚动。停止有二次确认。

> **关掉控制中心 ≠ 停止任务。** 要停必须选中账号后点界面里的「停止」。

## 4 · 四个视图详解

### ① 概览 — 回答"现在能不能启动、在跑什么"
- **启动前检查**:Core/设备/任务/实时通道四项,任一不过则禁用启动并给一键跳转。
- **任务调度**:正在执行 / 待执行 / 等待时间到达,看得到"下一个几点跑什么"。
- **最近日志**:最新几条,快速看有没有报错。

### ② 任务 — 目录在左,配置在右
- **点名称 = 看配置,右侧开关 = 启用/停用**(最关键的区别)。
- 搜索按 `/` 聚焦;可勾"只看已启用"。
- 改过的字段标黄"未保存",**只提交改动的字段**(旧版会整表回写,重置排期)。
- 可"放弃改动"整体还原,或单字段"恢复默认"。
- 时间间隔拆成"天数+时分秒"两个控件,不用手敲格式。
- 切换任务/账号/视图时,有未保存改动会先弹确认。

### ③ 日志 — 整屏,可过滤可导出
- 三个级别按钮(信息/警告/错误)切换显示,排查时只留"错误"。
- 支持搜索、自动滚动开关、导出 txt。
- Bridge 内存保留每账号最近 300 条;完整日志在项目 `log` 目录。

### ④ 设置 — 外观 / 连接 / 模板 / 账号管理
- **外观**:深色/浅色/跟随系统;舒适/紧凑密度(小屏建议紧凑)。会记住。
- **连接**:Bridge 地址、Core 状态、实时通道状态、立即重连。
- **配置模板**:管理已存模板。
- **当前账号**:重命名、删除(删除会删 Core 配置文件,不可撤销,有二次确认)。

## 5 · 多账号 / 多窗口

每个账号是 OAS 的独立配置工作区,任务/参数/状态/日志相互独立,切换不串线。

> **"多窗口"要你自己保证设备不同。** 要两个游戏窗口同时工作,得给每个账号在「运行设置」配*不同的*设备序列号/模拟器/窗口句柄。控制中心不会凭空造窗口,两个账号绑同一窗口会互相打架。

**新建账号**:点账号栏 `＋`。留空则 Core 自动命名;填了用你的。新账号先绑设备再启动。

---

## 6 · 配置模板 — 跨账号复用参数

1. 「任务」页选中任务、调好参数;
2. 展开"配置模板",输入名字,点**存为模板**;
3. 切到另一账号的同名任务,选模板、点**套用**;
4. 确认后点**保存**才真正写入(套用只是填进表单)。

> 模板存在 Bridge 数据库,可随数据库备份。套用不会套调度时间(next_run),避免打乱目标账号排期。

## 7 · 常见问题

- **"Core 未连接"** — 启动 OAS Core;确认 `Invoke-RestMethod http://127.0.0.1:22267/test` 返回 `success`。Core 用别的端口:`.\start-bridge.ps1 -CoreUrl http://127.0.0.1:22270`。
- **"等待 Bridge"或任务空** — 查 `http://127.0.0.1:22367/api/v1/health`;开发模式必须从 `http://127.0.0.1:4175` 打开,不能直接开 dist/index.html。
- **读不到窗口** — 先开模拟器/游戏窗口,再点"刷新窗口"。仅 Windows 有效。
- **保存失败(红提示)** — 看提示内容,通常是取值超范围(界面会明说)。别手改 config/*.json 绕过。
- **端口冲突** — `Get-NetTCPConnection -State Listen | ? { $_.LocalPort -in 22267,22367,4175 }` 查占用,确认 PID 再处理。
