0先弄懂一件事

控制中心不重写阴阳师的自动化逻辑,它只是给原来的 OAS 装了一个更好用的中文操作台。整套程序分三层,各司其职:

层是什么你要不要管它
OAS Core原项目本体,真正执行任务、控制模拟器
server.py · 端口 22267		必须先启动它,任务才能跑
Bridge中间适配层,把 Core 的接口翻译成界面好用的形式
端口 22367		桌面版会自动带起;开发模式用脚本启动
前端(本界面)你实际点的操作台
端口 5173 / 4175		就是你看到的窗口

记住一句话:控制中心不会替你开游戏、开模拟器。它管的是"哪个账号跑哪些任务、参数怎么配、现在什么状态",游戏窗口得你自己先开好。

1启动程序

日常直接双击 启动.bat;下面 A/B/C 是它背后对应的三种手动方式,打开的是同一个界面。

最简单 · 双击 D:\OSAyys\启动.bat

一键脚本会按 Core → Bridge → 界面 逐层处理:已在跑的直接复用,绝不重复启动;端口被陌生程序占用时,Bridge/界面自动换空闲端口(Core 端口是全局约定,不自动换,会停下报告占用进程);没在跑的在新窗口拉起并轮询等就绪(Core 首次含 OCR 初始化,最多等 90 秒;界面首次要装依赖,可能几分钟)。全部就绪后自动打开浏览器。

可选参数(在 PowerShell 里跑 .\control-center\start.ps1 时可加):-SkipCore 你已自行启动 OAS · -Prod 用生产前端(:5173) · -NoBrowser 不自动开浏览器 · -CoreUrl 指定 Core 地址

方式 A · 桌面版(推荐日常使用)

最省事。双击 portable 程序即可,它会自动带起 Bridge。前提是 OAS Core 已经在运行(照原项目的方式启动 server.py,或你平时怎么开 OAS 就怎么开)。

# 若还没有桌面版,先打一个（用 UI-claude 这套新界面）
cd D:\OSAyys\control-center\desktop
.\build.ps1 -SkipNpmInstall -Ui UI-claude
# 产物：control-center\desktop\release\OAS-Control-Center-0.1.0-portable.exe

之后每次用,先确认 Core 在跑,再双击 portable 程序。

方式 B · 开发模式(要改界面/调试时)

# 1) 先确保 OAS Core 在跑（默认 127.0.0.1:22267）
# 2) 起 Bridge + 前端
cd D:\OSAyys
.\control-center\launcher\start-all.ps1
# 3) UI-claude 新界面：
cd D:\OSAyys\control-center\desktop\release\UI-claude
.\start-ui-claude.ps1
# 打开 http://127.0.0.1:4175/

方式 C · 试用模式(不想开游戏,只想看看界面)

用内置的"模拟 Core",不连真实游戏、不碰任何真实配置、不启动任务。适合演示、熟悉界面、或上游更新后快速回归。

cd D:\OSAyys
.\control-center\launcher\start-dev-stack.ps1
# 一条命令拉起 模拟Core + Bridge + UI-claude，打开 http://127.0.0.1:4175/
拿不准三层通没通? 跑 .\control-center\check-wiring.ps1,它会逐层只读探测(不改任何东西),哪层先红就先修哪层。

2界面导览

整个界面是左边一列账号 + 右边四个视图。顶部永远显示当前账号和启动/停止按钮。

左侧 · 账号栏

每个账号对应 OAS 的一个配置文件,任务、参数、日志相互独立。点头像切换账号,底部 ＋ 新建账号。每张卡片显示状态点(运行中/已停止)和已启用任务数。

顶部 · 操作条

显示当前账号名、状态、设备。右侧是启动 / 停止 / 刷新。四个标签:概览、任务、日志、设置。任务标签上若有黄色数字,表示有未保存的配置改动。

3日常使用流程

从打开程序到任务跑起来,标准走这 7 步:

1
确认 Core 在线左上角显示"Core 在线"(绿点)才能往下走。灰的就先启动 server.py。
2
选账号左侧点你要操作的账号。任务、配置、日志都会跟着这个账号走。
3
去「任务」页配置点任务名只是看配置,不会启用;右边的开关才是启用/停用。把要跑的任务打开。
4
绑定设备打开「运行设置 → 设备连接」,选这个账号要控制的模拟器窗口。这一步配错,所有任务都会失败。
5
调参数并保存改过的字段会标黄"未保存"。确认无误后点保存(或 Ctrl+S)。只有保存过的字段才会写进 Core。
6
回「概览」过启动前检查四项检查(Core / 设备 / 任务 / 实时通道)全绿,启动按钮才可点。有红项,点旁边的按钮直接跳去修。
7
点启动,去「日志」看启动后状态变"运行中",日志会实时滚动。要停就点停止(会二次确认)。
关掉控制中心 ≠ 停止任务。 要停自动化任务,必须选中正确账号后点界面里的「停止」。

4四个视图详解

① 概览 — 回答"现在能不能启动、在跑什么"

  • 启动前检查:Core 连没连、设备绑没绑、有没有启用任务、实时通道正不正常。任何一项不过,启动按钮禁用,并给出一键跳转去修。
  • 任务调度:Core 回传的排期 — 正在执行 / 待执行 / 等待时间到达,能看到"下一个跑什么、几点跑"。
  • 最近日志:最新几条,快速扫一眼有没有报错。

② 任务 — 目录在左,配置在右

  • 点名称 = 看配置,右侧开关 = 启用/停用。这是最关键的区别,开关是标准样式,状态一眼可见。
  • 搜索框支持按 / 快速聚焦;勾"只看已启用"可以过滤。
  • 配置表单里,改过的字段标黄"未保存",标题栏显示"N 项未保存"。只提交你改动的字段,不会动别的(旧版会把整张表回写,导致排期被重置)。
  • 不满意可以点"放弃改动"整个还原,或单个字段"恢复默认"。
  • 时间间隔这类字段(如成功/失败间隔)拆成了"天数 + 时分秒"两个控件,不用手敲格式。
切换任务/账号/视图时,如果有没保存的改动,会先弹确认,不会让你悄悄丢配置。

③ 日志 — 整屏,可过滤可导出

  • 顶部三个级别按钮(信息/警告/错误)点一下切换显示,排查问题时只留"错误"很方便。
  • 支持搜索日志内容、自动滚动开关、一键导出成 txt。
  • Bridge 在内存里保留每个账号最近 300 条;完整日志仍在项目的 log 目录。

④ 设置 — 外观、连接、模板、账号管理

  • 外观:深色 / 浅色 / 跟随系统;舒适 / 紧凑密度(小屏或 1280×760 建议紧凑)。选择会记住。
  • 连接:Bridge 地址、Core 状态、实时通道状态,一个"立即重连"按钮。
  • 配置模板:管理已保存的模板(见第 6 节)。
  • 当前账号:重命名、删除。删除会删掉 Core 里的配置文件,不可撤销,有二次确认。

5多账号 / 多窗口

每个账号是 OAS 的一个独立配置工作区 — 独立的任务开关、参数、状态、日志。切换账号,这些都跟着换,不会串线。

"多窗口"要你自己保证设备不同。 要让两个游戏窗口真正同时工作,得给每个账号在「运行设置」里配不同的设备序列号 / 模拟器 / 窗口句柄。控制中心不会凭空造窗口,也不保证两个账号连到了不同设备 — 两个账号绑同一个窗口会互相打架。

新建账号:点账号栏的 ＋。留空名字则由 Core 自动命名(oas2、oas3…);填了名字就用你的。新账号记得先绑设备再启动。

6配置模板 — 跨账号复用参数

把一个任务调好的全部参数存成模板,套用到别的账号的同一任务,省得重复配。

  1. 在「任务」页选中任务、调好参数;
  2. 展开"配置模板",输入名字,点存为模板;
  3. 切到另一个账号的同名任务,选模板、点套用;
  4. 确认参数后点保存 — 套用只是填进表单,保存了才真正写入那个账号的 Core 配置。
模板存在 Bridge 的数据库里,可以随数据库一起备份,换浏览器不会丢。套用时不会套调度时间(next_run),避免打乱目标账号的排期。

7常见问题

页面显示"Core 未连接"

先启动 OAS Core。确认命令:Invoke-RestMethod http://127.0.0.1:22267/test 应返回 success。若 Core 用了别的端口,启动 Bridge 时指定:.\start-bridge.ps1 -CoreUrl http://127.0.0.1:22270

显示"等待 Bridge"或任务空

检查 http://127.0.0.1:22367/api/v1/health。开发模式必须从 http://127.0.0.1:4175 打开,而不是直接开 dist/index.html,否则接口代理不生效。

读不到窗口

先把模拟器/游戏窗口打开,再点"刷新窗口"。枚举窗口只在 Windows 上有效。

保存失败(红色提示)

看提示内容 — 通常是取值超出允许范围(界面会明确告诉你,比如"时间间隔最多 99 天")。别去手改 config/*.json 绕过,先看清报错。

端口冲突

Get-NetTCPConnection -State Listen | ? { $_.LocalPort -in 22267,22367,4175 } 查占用。先确认 PID 是不是本项目的进程再处理,别乱杀。
