## 5. 停用任务后的调度器行为

为避免测试任务按第二天的 `next_run=2026-08-07 00:30:32` 自动运行，使用现有控制中心接口停用了 `oas1/RyouToppa`：

```text
PUT /api/v1/accounts/oas1/tasks/RyouToppa/enabled?enabled=false
```

复查结果：

- `RyouToppa` 已禁用。
- 账号任务队列 `running/pending/waiting` 均为空。
- Core `127.0.0.1:22267`、Bridge `127.0.0.1:22367`、前端 `127.0.0.1:4175` 监听仍在；没有停止这些服务。
- 账号脚本子进程随后退出，日志为 `Script process exited: account=oas1 ... exitcode=1`。

这次退出的直接根因不是寮突破业务，而是“账号没有任何启用任务”时调度器没有空闲状态：

```text
module/config/config.py:240  No task waiting or pending
module/config/config.py:242  raise RequestHumanTakeover
module/server/script_router.py:214  config.get_next()
```

随后 websocket 报 `Run script oas1 error`，控制中心显示账号 `offline`。这属于调度器停用路径缺陷，建议单独作为 P1 处理：停用全部任务后应进入明确的 idle/stopped 状态，不应以异常退出和 traceback 结束。当前未修改该逻辑，避免把调度器改动与本轮寮突破实测混在一起。

## 6. 本轮结论

1. 结算回板修复在 50 场长程中未再触发 `RYOU_BOARD_RETURN_TIMEOUT`，战斗链路稳定性得到实机支持。
2. 本轮未完成寮突破业务闭环，只完成了 50 场长程稳定性验证；任务结束原因为计数上限。
3. 棋盘状态始终为 `1:failed`、其余可用并持续选择 2 号位，必须用当前版本棋盘截图和模板做离线逐项核验后再修复。

5. 停用全部任务会暴露 `RequestHumanTakeover` 空任务退出问题；本问题已记录，暂不在本轮修复。
