# 05 多账号多窗口说明

## 当前实现方式

OAS Core 的每一个配置名都对应一个独立账号配置。例如：

```text
config/template.json  →  config/oas1.json
                    →  config/oas2.json
                    →  config/oas3.json
```

Bridge 为每个账号创建独立的 `AccountRuntime`：

- 独立的 OAS WebSocket 地址：`/ws/{account_id}`；
- 独立的状态字段；
- 独立的调度快照；
- 独立的日志缓冲区；
- 启动、停止、重启命令带有明确的账号 ID。

因此，控制中心支持多个账号各自配置不同任务，并在逻辑上独立运行，账号切换不会共用任务开关或日志。

## “多窗口”的实际含义

前端的“账号 / 窗口”代表一个 OAS 配置工作区。要让多个阴阳师游戏窗口真正同时工作，还需要给每个账号在“运行设置”中配置不同的设备序列号、模拟器名称、窗口句柄或客户端信息。控制中心不会凭空创建模拟器窗口，也不会自动保证两个账号连接到了不同设备。

## 新建账号

点击账号列表旁的 `＋`：

- 不填写名称时，Bridge 调用 Core 的 `/config_new_name` 生成名称；
- 填写名称时，Bridge 调用 Core 的 `/config_copy` 从 `template` 复制；
- 昵称、头像、标签和设备显示名属于 Bridge 的 UI 元数据。

## 账号隔离注意事项

- 不要让两个账号使用同一个设备序列号或同一个窗口句柄；
- 不要在一个账号的模板应用后忘记切换到目标账号再保存；
- 启动/停止前看顶部账号名称和 ID；
- 删除账号会调用 Core 的 `/config` 删除配置文件，属于有副作用操作；
- Bridge 进程重启不会删除 Core 配置，但会清空内存中的实时日志缓存。

## 当前验证边界

本次回归只在不启动任务、不改变用户配置的前提下验证了账号加载、独立配置读取和事件连接。多账号同时启动需要真实设备和游戏窗口，接手者应在测试账号、测试设备上单独验收，不要直接用生产账号做压力测试。
