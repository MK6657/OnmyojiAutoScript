# Codex-55 寮突破勋章排序单步测试计划

日期：2026-08-07  
分支：`codex/mk6657-secondary-development`

## 1. 本轮结论

本轮真实入口测试证明：寮突破前置、预设切换、进入个人突破入口和进入棋盘均可执行，但“自动选择最高勋章寮”尚未实现正确。

当前实现的实际链路是：

`点击勋章奖励` -> 假定已经降序 -> 固定点击第一张寮卡

代码没有读取任何寮卡的勋章数，也没有比较点击排序前后的两种顺序。因此，排序按钮如果当前切换为升序，第一张卡就是勋章最低的寮。本轮实机已经出现该问题，用户确认所选寮为勋章最低项。

## 3. 明晚首要任务：单步验证

只验证寮选择，不直接进入长程寮突破。每一步都停顿到画面像素稳定后再进行下一步。

1. 保证当前没有已选择的目标寮，进入“选择阴阳寮”列表。
2. 读取当前排序状态下所有可见寮卡的勋章数，记录卡片位置、寮名（仅用于现场核对）和勋章值。
3. 点击“勋章奖励”排序按钮一次。
4. 等待页面转场结束，并要求连续新帧像素稳定后，再读取所有可见寮卡的勋章数。
5. 将点击前、点击后的实际勋章值进行对比，判断当前是升序还是降序；不依据按钮点击次数或固定位置推断。
6. 如当前最高勋章不在第一张卡，继续切换排序并等待稳定；最终以实际读取到的最大勋章值确定目标卡。
7. 点击对应的目标寮卡，确认弹出的寮信息与记录的最高勋章候选一致。
8. 点击“突入开始”，只确认进入寮突破棋盘；本单步测试到棋盘确认即停止。

## 4. 验收标准

- 日志必须同时包含排序前后每张候选卡的勋章值，而不是只记录 `rank=1`。
- 选择结果必须满足 `selected_medal == max(observed_medals)`。
- 排序按钮点击后，至少有稳定等待和新帧确认；未稳定时不得读取或点击卡片。
- 最高勋章不在第一张时，不能点击固定第一张卡。
- OCR 不完整、数值冲突或最高值无法确认时，停止选择并记录 `guild_medal_compare_unconfirmed`，不得随机选择。
- 进入“突入开始”前，目标卡的实际勋章值和位置必须有日志证据。
- 测试结束后恢复寮突破关闭状态，不启动其他任务。
