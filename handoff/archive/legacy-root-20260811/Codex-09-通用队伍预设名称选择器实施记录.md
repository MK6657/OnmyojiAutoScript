# Codex 09 通用队伍预设名称选择器实施记录

日期：2026-08-03  
适用分支：`codex/mk6657-secondary-development`  
状态：代码、离线验证与真实 RealmRaid 预设应用闭环均已完成；最终实测见 `Codex-11-个人突破预设应用与第九胜实测闭环.md`。

## 1. 本次目标

把上游 `GeneralBattle` 的“固定分组序号 + 固定队伍序号”切换方式，迁移为适配当前游戏界面的“分组名称 + 队伍名称”选择方式，并保留旧配置读取能力。

已确认的当前游戏结构：

1. 右侧是预设分组，分组可新增、删除、重命名和调整顺序。
2. 中间是当前分组下的队伍预设，队伍数量不固定，可向下滑动。
3. 重新打开队伍预设后，队伍列表回到顶部。
4. 点击目标队伍最右侧的应用图标后会出现确认弹窗，点击“确定”完成切换。
5. 队伍名称允许重复；程序识别到同名目标时必须停止，不能默认选择第一个。

## 2. 原实现问题

原入口为 `tasks/Component/GeneralBattle/general_battle.py::switch_preset_team`。

原实现存在以下版本冲突：

1. 分组固定点击旧界面左侧 `1~7` 坐标，与当前右侧分组列表不一致。
2. 队伍只定义了前四行点击资源，但配置模型允许 `1~5`；选择第 5 队会触发属性不存在。
3. 不识别分组名和队伍名，用户重排、插入或删除内容后会选错。
4. 不处理队伍列表滚动，目标不在首屏时无法定位。
5. 没有名称重复保护，可能静默选择错误队伍。
6. 旧确认按钮素材属于历史界面，不是当前中央确认弹窗。
7. `SwitchSoul` 虽有名称 OCR 和当前界面坐标，但找不到目标时可能无限滑动，也没有重名检查，不能直接照搬。

## 3. 新执行链路

```text
GeneralBattleConfig
  -> preset_enable=true
  -> lock_team_enable=false
  -> 第一次进入战斗准备界面
  -> 打开当前版本队伍预设
  -> 右侧分组列表回顶并扫描到底
  -> 分组名称必须唯一
  -> 点击目标分组并等待列表更新
  -> 中间队伍列表回顶并扫描到底
  -> 队伍名称必须唯一
  -> 回顶后再次定位目标队伍
  -> 点击该行最右侧应用图标
  -> 点击“确定”
  -> 识别成功/已使用提示；未捕获提示时以弹窗稳定消失作为降级证据
  -> 返回战斗准备界面
```

列表扫描使用“上一页后缀与下一页前缀的最大重叠”合并结果。这样可去掉滚动重叠造成的重复行，同时保留真实相邻同名队伍。例如第一页为 `队伍1, 队伍2, 队伍2, 队伍3`，下一页为 `队伍2, 队伍3, 队伍4`，最终仍保留两个 `队伍2` 并触发重名错误。

名称匹配只做全角/半角、大小写和空白规范化，不做模糊匹配。OCR 结果与用户输入不一致时宁可停止，也不猜测目标。

## 4. 配置兼容

新增每个 `GeneralBattleConfig` 自带字段：

- `preset_group_name`：右侧预设分组完整名称。
- `preset_team_name`：中间队伍预设完整名称。

历史字段 `preset_group`、`preset_team` 仍保留在 Core 模型中：

- 两个名称均填写：走当前版本名称选择器。
- 只填写一个名称：配置不完整，进入战斗前停止。
- 两个名称均为空：继续走旧固定序号逻辑，保证旧账号配置不会因升级立即失效。

控制中心检测到名称字段时会隐藏两个旧数字字段，避免新配置继续依赖不稳定序号。

## 5. 安全边界

以下情况都在点击“准备”前停止，不会用不确定队伍开战：

1. 分组名称或队伍名称只填写一个。
2. 找不到目标分组或队伍。
3. 扫描到多个同名目标。
4. OCR 连续为空、列表无法回顶或无法判断到底。
5. 点击应用图标后没有确认弹窗，也没有“已使用预设”提示。
6. 确认后弹窗不消失，或无法返回战斗准备界面。

名称配置错误使用 `RequestHumanTakeover` 停止当前账号进程，不调用游戏重启。这样不会因为队伍预设重名去杀掉游戏并影响其他进程。

## 8. 2026-08-03 真实页面兼容补充

对 `2301` 做只读扫描后确认：`日常` 分组全局唯一，分组内 `结界突破` 队伍唯一，且列表回顶后稳定处于第一行。首次执行名称选择器没有产生点击，原因是上游 `I_SOU_CHECK_IN` 图片素材已不匹配当前游戏版本，程序虽然已处于队伍预设页，仍等待旧模板直至超时。

页面判定现改为两级兼容：优先保留旧模板快速路径；旧模板未命中时，OCR 右侧预设分组区域，并要求至少三个有效名称以及至少两组符合当前列表行距的相邻行。该结构条件只用于确认是否已进入或已经离开队伍预设页，不改变分组、队伍名称的唯一匹配规则。

真实点击 `结界突破` 行最右侧应用图标后，当前版本会弹出“即将为全队式神更换预设御魂”的确认框，但上游 `I_SOU_SWITCH_SURE` 图片素材无法命中，旧流程会等待六秒后安全停止。确认逻辑现增加 `确定` 文字 OCR 兜底，并在确认后同时用旧模板和 OCR 检查弹窗确实消失，避免把模板失效误判为切换成功。

独立实测进程还发现 `ConnectionAttr.adb_binary` 误把 `sys.executable` 文件路径当成目录拼接，项目虚拟环境内虽然已有 `adbutils/binaries/adb.exe`，运行时仍显示 `AdbBinary=adb` 并依赖系统 PATH。现改为从已导入的 `adbutils` 包目录定位内置 ADB，并保留仓库候选路径和系统 PATH 两级回退。
