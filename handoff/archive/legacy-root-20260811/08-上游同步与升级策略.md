# 08 上游同步与升级策略

## 原则

OAS Core 是上游事实来源，控制中心是独立适配层。同步上游时优先保持 `module/`、`tasks/` 和原 QML 的原貌，控制中心只适配公开接口和 Schema。

## 同步步骤

1. 记录当前 OAS commit、配置文件备份和控制中心版本；
2. 更新上游代码或替换上游发布包；
3. 先单独启动 Core，确认 `GET /test` 返回 `success`；
4. 对比 `GET /script_menu`：任务 ID、分组和任务数量是否变化；
5. 对主要账号读取 `/{config}/{task}/args`，检查字段类型、分组、enum 和日期时间格式；
6. 检查 `/ws/{config}` 的状态、调度和文本日志消息格式；
7. 先修 `bridge/app/core_client.py`、`main.py`、`runtime.py` 的协议适配；
8. 再修 `frontend/src/locale.js` 的中文映射；
9. 重新执行测试报告中的命令；
10. 在测试账号和测试设备上验收启动、停止和多账号隔离后再上线。

## 重点兼容点

- Core 默认端口是否仍为 22267；
- `/script_menu` 返回的是字典还是其他结构；
- 任务 ID 是否重命名；
- Schema 的 `type` 是否出现新类型；
- enum 字段是否使用 `enum` 或 `enumEnum`；
- `date_time`、`time` 的值格式是否仍能被 Core 接受；
- WebSocket 状态值是否仍使用 0/1/2/3；
- 账号复制、删除、重命名接口参数是否改变。

## 遇到 Core Bug 时

先判断问题属于哪一层：

- Core 原任务/设备/调度逻辑错误：记录上游版本、复现步骤和原始响应，按原项目流程修复或等待上游修复；
- Bridge 映射错误：只改 `control-center/bridge`，补测试；
- 中文或交互错误：只改 `control-center/frontend`；
- 桌面启动/打包错误：只改 `control-center/desktop` 和构建脚本。

如果确实必须修改 Core 文件，必须在变更记录中写明：文件、原因、上游 commit、是否可回迁、回迁步骤。不要把临时修复混在上游同步提交中。

## 建议的版本标记

每次同步至少记录：

```text
OAS Core commit/tag:
Control Center version:
Bridge contract version:
Test date:
Known incompatibilities:
```
