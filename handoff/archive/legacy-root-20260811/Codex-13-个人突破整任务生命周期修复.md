## 1. 问题纠正

个人突破的一次业务任务是：调度器按 `next_run` 拉起 RealmRaid 后，由 RealmRaid 自己持续执行，直到突破券达到用户设置的保留值、刷新进入冷却、证据不安全或发生其他明确阻塞。

此前的受限批次实现把开发验收边界误当成业务任务边界：

```text
single_step=true
  -> 每次只提交一个动作
  -> finish_level_mode(success=False)
  -> 返回庭院
  -> 按 failure_interval 排到次日

single_step=false + max_actions_per_run=13
  -> 最多完成一张棋盘的退四打九
  -> 即使仍有突破券也按相同出口结束
```

因此 Codex-12 验证的是“单棋盘退四打九闭环”，不是“刷完当前全部突破券的整任务闭环”。从 26 张券打到 17 张券后退出的事实仍有效，但任务完成范围必须按本文件纠正。

## 2. 修复后的职责边界

```text
Core 调度器
  -> 只负责选择并拉起到期的 RealmRaid

RealmRaid 正式模式
  -> 识别棋盘和 checkpoint
  -> 按降级 / 保级 / 升级决策执行动作
  -> 每个动作独立保存 pending 并用画面证据提交
  -> 自动换板后重新识别九格并继续
  -> 票数达到保留值时才正常完成

RealmRaid 可以交回调度器的边界
  -> COMPLETED：票数达到保留值或本次成功耗票额度达到配置值
  -> DEFERRED：刷新冷却，按 OCR 剩余时间精确调度
  -> PAUSED：证据不安全、动作无法确认或异常看门狗触发
  -> TEST_PAUSED：显式开启单步测试后只完成一个动作
```

前端显示的账号“运行中”仍只表示账号调度进程存活，不等于 RealmRaid 正在战斗。进程、任务和工作流三层状态显示属于后续控制中心修复，不在本轮扩大修改范围。

## 3. 本轮代码修改

1. `single_step` 默认值改为 `false`，账号 `oas1` 同步关闭单步测试。
2. 删除 `max_actions_per_run` 配置和正式批次结束语义。
3. 正式模式执行动作后继续留在 `run_level_mode()`，不再在第 13 个动作后调用任务结束接口。
4. `number_attack` 在目标等级模式中按本次实际成功消耗的突破券计数；自然战败不消耗券，也不占成功耗票额度。
5. `number_base` 成为正式业务完成边界；设为 0 表示尽量刷完当前突破券。
6. 保留内部异常事务看门狗，默认配置下为 120 个已提交动作。它只防止异常长循环，不替代票数完成条件。
7. 事务看门狗检查放在票数完成判定之后，最后一个动作恰好把券刷完时会记为正常完成。
8. `finish_level_mode()` 增加 `outcome/reason` 日志，区分完成、冷却延期、测试暂停和异常暂停。
9. 重复投降若在“回到棋盘”和“提交 checkpoint”之间中断，由于原目标已有失败箭头、画面无法证明本次是否完成，恢复时只清除 pending、不增加逻辑失败数，并安全重放一次。这样可能多投降一次，但不会少算保级/降级所需失败，也不会永远卡在同一个 pending。
10. 已确认战败不会触发自动换板，因此战败回板时即使名字区域签名轻微漂移，也不再清空当前 checkpoint；第九胜后的自动换板仍按成功数归零、破印归零和票数减少确认。

每次动作的 checkpoint、九格众数、破印、失败次数、票数交叉验证、3/6/9 奖励处理、第九胜自动换板和 CD 精确调度均保持原实现。

## 4. 数学边界

满 30 张券、每一代棋盘都需要保级且全部挑战成功时，最多会经历：

```text
4 代棋盘 × 4 次投降 + 30 次胜利 = 46 个动作
```

旧配置最大只允许 40 个动作，理论上无法保证一次刷完。新正式模式没有 13/40 的业务批次上限，内部 120 动作看门狗可覆盖正常满票保级流程及合理数量的自然战败。

## 7. 独立审查结论与保留项

子代理只读审查确认：`single_step=false` 时，单次投降、战斗和单棋盘完成均不会再结束整个 RealmRaid，正式循环可以跨棋盘继续。审查提出的重复投降 pending、战败签名漂移和缺少直接状态机测试，已在本轮补齐。

1. `number_attack` 的实际耗票额度当前按一次 Python 调用计算，不跨刷新 CD 或异常暂停持久累计。`oas1` 配置为 30，而游戏票上限也是 30，当前“刷完券”流程不会超额；如果以后允许用户设置小于持有票数的严格跨恢复额度，应增加独立于棋盘 checkpoint 的任务会话账本。
2. 目标等级模式的识别异常使用 `TaskEnd` 交回调度器，顶层将其视为该次调度已结束。这是此前确定的安全策略：只停止 RealmRaid、继续其他任务、不触发全局重启或连续三次失败后关闭模拟器。后续应在控制中心增加 `PAUSED/DEFERRED` 工作流状态，而不是直接把它改成会连累账号进程的全局失败。
