# 坐标标注操作台审计与后台帧源修复

日期：2026-08-07
范围：`D:\coordinate-calibrator`、MuMu 实例 `2301` / ADB `127.0.0.1:16384`

## 结论

本次反馈对应的故障已定位并修复。窗口选择器显示 `2301` 为“窗口已最小化”，这是前台可见窗口模式的安全限制；它不代表 MuMu 没有画面。此前虽然存在 Nemu IPC 适配器，但没有接入无需窗口绑定的会话启动路径，而且在 FastAPI 事件循环中直接初始化 OAS Nemu 实现会触发事件循环冲突。

当前后台帧源链路已经实测通过：不选择窗口即可创建会话，选择 `nemu_ipc`，开始采集并保存真实 `1280x720`、`RGB` 帧。来源身份为 serial `127.0.0.1:16384`、instance `0`、config `oas1`。

工具读取的是 MuMu Nemu IPC 帧缓冲，不使用 `ReadProcessMemory`，也不向 OAS 业务配置写回。

## 审计摘要

四个只读审计角色共同确认：

- 重启后外部帧源可能丢失，旧实现会静默退回屏幕截图。
- Nemu/A DB、屏幕和窗口 DPI/遮挡/身份契约仍缺少完整实机验证。
- 帧、样本、标注和导出配额尚未真正执行，session 删除后的 artifact 清理仍需治理。
- 部分前端实时操作会覆盖本地租约，导致后续写请求出现 `session lease is required`。
- 实时鼠标采集只能使用前台窗口模式；后台 Nemu/ADB 只能读取帧和在画布上标注，不能从屏幕鼠标位置反推坐标。

上述治理项没有在本次故障修复中扩大修改范围，继续保留为开放事项。

## 本次修复

### 后端

- `NemuIpcFrameSource` 支持从 `config.local.toml` 自动读取 OAS 根目录和配置名。
- Nemu 连接、截图和释放固定在单独工作线程，避免与 FastAPI 请求事件循环冲突。
- 后台 `adb` / `nemu_ipc` 来源无需 HWND 或窗口映射，自动建立画布坐标映射。
- 外部来源严格校验 frame source 和 source identity。
- 服务重启后无法恢复外部来源时进入 `rebind_required`，禁止回退为屏幕截图。
- 后台来源下拒绝鼠标采集，避免生成没有屏幕映射依据的样本。
- Nemu 的公开身份不再返回 OAS 根目录绝对路径。

### 前端

- “绑定游戏画布”在 ADB/Nemu 模式下不再阻塞流程，并提示无需选窗口。
- 后台帧源显示独立的 canvas 映射信息。
- 后台帧源下禁用鼠标采集按钮。
- 保留绑定、开始采集、应用来源、保存帧和停止采集之间的服务端租约。

### 配置

新增本机忽略文件：`D:\coordinate-calibrator\config.local.toml`。它只保存本机 OAS 根目录，不提交到版本库。

## 当前使用方式

1. 打开 `http://127.0.0.1:22880/`，展开“实时窗口校准”。
2. 点击“创建实时会话”。
3. 在“截图来源”选择 `Nemu IPC`，点击“应用截图来源”。
4. 点击“开始采集”，再点击“保存当前帧”。
5. 画面出现后可在标注画布上使用点、框、圆、椭圆、三角和画笔。

只有需要采集真实鼠标点击样本时，才选择前台窗口并绑定有效画布。`2301` 最小化时不能使用该模式；后台 Nemu 模式不受最小化影响。
