## 2. 实机画面证据

### 2.1 普通式神录误判：已确认

Computer Use 对当前 `2301` 窗口的只读截图显示：

- 页面标题为“式神录”。
- 左上方可见普通式神录的搜索按钮、`预设`按钮和列表按钮。
- 页面主体仍是式神卡片和当前式神详情。
- 没有预设页右侧分组列表、中央队伍预设卡片和队伍标题列表。

同时查看模板文件 `tasks/Component/SwitchSoul/ss/ss_sou_check_in.png`，其图像内容是普通式神录左上方的放大镜搜索图标；文件注释也写明它用于判断“是否在式神录里面”。

当前代码在 `tasks/Component/GeneralBattle/general_battle.py:666-669` 仍然是：只要 `I_SOU_CHECK_IN` 出现，就立即返回 `True`。因此普通式神录页满足该模板时，会被当成“当前已经在预设页”，跳过真正点击 `预设` 入口。该项由真实画面和代码共同确认，属于高置信 P0/P1 页面状态判定错误。

### 2.2 历史预设页截图：未显示真实重名

- 右侧分组列表中只看到一个“日常”卡片。

- 该截图没有出现两个同时可见、同名为“日常”的分组行。

这张截图不能证明 10:30 运行时的完整分组数据绝对没有重名，但可以证明“程序曾经成功打开真实预设页”与“页面上可见一个日常分组”是两件不同的事实，不能把 OCR 的重复计数直接等同于游戏数据重名。

## 3. 10:30 运行日志复核

证据文件：`log/2026-08-05_oas1.txt`，重点行 `32635-32660`。

- `32635` 点击 `SS_SOUL_PRESET`，说明程序确实执行了打开预设入口。
- `32636`、`32640`、`32646`、`32648`、`32650` 都识别到同一页的完整分组列表，其中每一帧仅出现一个“日常”。
- `32653` 之后列表发生滚动，变成 `['逢魔', '秘闻', '日常', '活动', '挂机', '僵尸寮', '契灵', '地域鬼王']`，该帧仍然只有一个“日常”。
- `32659` 抛出“识别到 2 个同名预设分组‘日常’”。

日志没有任何一帧在同一个可见列表中同时检测到两个“日常”。所以这次日志只能证明“合并后的跨页序列中出现了两个日常”，不能证明游戏里存在两个真实分组。

## 4. 根因推断：跨页重叠合并被 OCR 变体打断

当前 `GeneralBattle._scan_preset_names()` 在 `general_battle.py:739-753` 使用 `merge_ordered_pages()` 合并滚动页面；`preset_name_selector.py:83-103` 只按字符串序列寻找最大后缀/前缀重叠。

从日志还原的相邻页面：

```text
页面 A: 御魂, 逢魔, 秘闻, 日常, 活动, 挂机, 侵尸寮, 契灵
页面 B: 逢魔, 秘闻, 日常, 活动, 挂机, 僵尸寮, 契灵, 地域鬼王
```

页面 B 中的“僵尸寮”很可能是同一行“侵尸寮”的 OCR 变体。由于重叠区域包含这个不一致字符串，严格序列匹配找不到正确的重叠前缀，于是把页面 B 整页追加到页面 A；这样同一个“日常”被追加第二次，`require_unique_name()` 在 `preset_name_selector.py:106-122` 将其当成真实重名并触发人工接管。

因此本次“两个日常”的结论应从“真实重名”降级为：

> 高置信的 OCR 跨页合并误报；真实重名仍需在同一帧同时检测到两个目标行后才能确认。

## 5. 与审计报告的交叉结论

### 已由实机确认

- `I_SOU_CHECK_IN` 是普通式神录搜索图标，不是预设页唯一标识。
- 当前 `_is_current_preset_page()` 的直接模板返回会造成普通式神录误判。
- 预设页必须依赖分组列表、中央队伍列表等结构联合确认。

### 目前不能直接采信

- 10:31 的“两个日常分组”不能作为游戏真实重名证据。
- 这次运行不能归因于用户必须重命名分组；在修正跨页合并或取得同帧双行截图前，不应要求用户改名。

### 仍需后续验证

- 在不修改账号数据的前提下，保存每次滚动后的 OCR 行文本及 `center_y`，区分“同帧重复行”和“跨帧重复行”。
- 对相邻页的重叠匹配增加 OCR 容错，但必须保留真正相邻同名分组的拒绝能力。
- 只有同一页同一列表中出现两个相同规范化名称，或跨页通过稳定行锚点确认两个不同位置的同名行，才报真实重名。
