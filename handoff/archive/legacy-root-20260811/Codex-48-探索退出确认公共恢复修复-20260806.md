# Codex-48 探索退出确认公共恢复修复

日期：2026-08-06
分支：`codex/mk6657-secondary-development`
账号：`oas1`
设备：MuMu `2301`，HWND `198230`，游戏分辨率 `1280x720`

## 问题

困28战斗结束或任务切换期间，游戏可能停在“确认退出探索吗？”弹窗。公共 `GotoMain -> GameUi.ui_get_current_page -> try_close_unknown_page` 没有探索专用退出确认标识时，会先识别到弹窗下方的左上角返回按钮 `UI_UI_BACK_YELLOW`，连续点击同一按钮，最终触发：

```text
Unknown ui page remains; skip unsafe SAFE_RANDOM_CLICK and wait for a supported close marker
Click UI_UI_BACK_YELLOW ...
Too many click for a button: UI_UI_BACK_YELLOW
GameTooManyClickError
```

原始错误截图：`log/error/1785989338347/2026-08-06_12-08-58-123070.png`。截图中的弹窗确认按钮位于 `(694,380,163,49)`，文字区域位于 `(735,378,100,34)`。

## 根因

这是公共未知页面恢复顺序问题，不是困28自动轮换候补逻辑，也不是队伍预设逻辑。探索退出确认弹窗覆盖了底层返回按钮；模板在当前皮肤下可能漏检，若没有 OCR 兜底，恢复队列就会操作底层控件。

## 修复

1. 在 `tasks/Exploration/assets.py` 增加窄范围 `O_E_EXIT_CONFIRM_TEXT` OCR 规则。
2. `tasks/Exploration/base.py` 复用该规则，避免探索退出流程和公共恢复流程使用两套坐标。
3. `tasks/GameUi/game_ui.py` 将探索退出模板和 OCR 规则放在 `ui_close` 队列最前面，优先关闭弹窗，再处理保护页、普通返回按钮。
4. `tasks/GameUi/tests/test_unknown_page_close.py` 增加回归用例，验证探索退出确认不会落到底层返回按钮。
