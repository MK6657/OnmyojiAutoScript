## 3. 必须修正的报告建议

### 3.1 不要禁止队伍预设和御魂预设同时存在

`Codex-27` 建议禁止 `enable_switch_by_name` 与 `preset_enable` 同时开启，这只能作为临时防重复执行护栏，不能作为最终业务方案。

用户已经确认的业务是：一次战斗前准备可能同时需要换队伍和换御魂。正确方向是：

- 保留“队伍预设”和“御魂预设”两个业务意图。
- 只保留一个权威的战斗前准备执行器。
- 由执行器根据阵容锁定状态决定先解锁、应用、确认和重新锁定。
- 旧 `SwitchSoul` 可以暂时作为兼容适配层，但不能和新入口重复点击同一页面。

也就是说，应当“合并执行路径”，不是“禁止业务组合”。

### 3.2 不要全局捕获所有 ValueError

配置中的 `-1,-1` 应在配置加载或任务启动预检阶段被发现。建议使用专用异常，例如：

- `InvalidPresetConfigError`
- `PresetLookupError`
- `PresetApplyUnconfirmedError`

只对这些预设相关异常安排短重试；不要在全局 `script.py` 中把所有 `ValueError` 变成重试，否则会吞掉其他模块的真正编程错误。

### 3.3 锁定规则已经由用户确认，不应反复要求确认业务

已确认的目标行为：

- 未锁定时，可以应用队伍预设和御魂预设。
- 已锁定但需要更换队伍时，先解除锁定。
- 解锁在限定时间内没有确认成功时，按兜底流程继续换御魂并允许当前场次完成。
- 战斗完成后尝试重新锁定。
- 重新锁定失败时，允许下一场点击准备，下一场结束后再重试锁定。

审查者应验证代码是否实现上述规则，不应把它当成新的业务问题反复上报。

### 3.4 少于五个式神暂不作为当前 P0

用户已经明确：少于五人的素材补位流程需要另外设计，当前先不处理。它可以记录为后续兼容缺口，但不能阻塞当前已有五人或六人队伍的主链路验收。

### 3.5 日志次数需要按精确模式重算

对当前日志使用完整字符串统计得到：

- `Scheduler: Start task Exploration`：42 次。
- `Scheduler: End task Exploration`：32 次。
- `Scheduler: Start task RealmRaid`：4 次。
- `Scheduler: End task RealmRaid`：3 次。

报告中的 `46/35` 与当前日志精确匹配结果不一致，应修正为实际统计值，并注明统计表达式和日志文件版本。

这些数字可以证明任务启动和结束不平衡，但不能单独证明存在两个进程并发控制游戏。没有 PID、run_id、请求来源时，只能标记为风险线索。

### 3.6 Nemu IPC 的表述要精确

准确结论是：

- Nemu IPC 读取模拟器当前原生帧分辨率，不依赖窗口显示大小。
- 当前 OAS 主路径要求 canonical 画面为 1280x720。
- 模拟器窗口缩小不应改变 IPC 画面。
- 如果模拟器输出分辨率本身改成其他尺寸，当前代码没有通用 resize 适配，并可能拒绝运行。


### 第二步：只验证预设前置，不直接长程刷票

验收条件：

- 当前队伍名和分组能稳定找到。
- 当前卡片布局上的实际应用控件被点击。
- 弹窗出现、确定、消失三态均有证据。
- 当前预设已生效时可以安全跳过，不误点。
- 预设失败不会全局 `exit(1)`。
- 日志出现 `Page arrived page_realm_raid` 后，才允许继续测试九格状态机。

### 第三步：修复 checkpoint 模式恢复

- target=58，current=57，旧 mode=hold，必须重新判定为 raise。
- target=58，current=58，旧 mode=hold，保留 hold。
- target=58，current=59，旧 mode=raise，重新判定为 lower。

- pending attack 的目标已在 `broken` 集合中，但无法证明是本次动作造成时，应进入 ambiguous，而不是自动提交。

### 第四步：处理困28确定性问题

顺序建议：

1. 用模板实际命中位置点击设置按钮。
2. 修复 `Restart` 禁用时的脏状态循环。

4. 给 `quit_explore()` 记录明确退出原因。

### 第五步：最后整理调度器

- `TaskEnd` 的结构化结果。
- 跨任务 `next_run` 写入权限。
- 新 Core、旧 QML、Bridge 和脚本入口的账号/设备所有权锁。
- PID、run_id、request_id 日志字段。
- 任务完整批次和调度器单次调用的边界。
