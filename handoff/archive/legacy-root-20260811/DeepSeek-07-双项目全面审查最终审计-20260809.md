## 三、边界问题与根因（最终版 TOP，模板化）

### P0-1 绿标确认在现客户端全任务 0 confirmed（模板结构性缺陷）
- 结论状态：已证实（静态+像素统计）；渲染差异部分待实机帧
- 源码控制流：`general_battle.py:1011` green_mark → `:1080` `_wait_green_marker_confirmation`（确认带 x±45/y−180..y+h+100，全屏搜 3 模板阈值 0.8）→ 0 命中 → 软失败继续 battle_wait（:139）
- 证据：**父代理像素统计**——`gb_green_marker.png` 37x17=629 像素含 **330 种颜色（52% 像素颜色唯一）**、暗色 42%、绿色调 58%；left_top 19x13 颜色 139/247；bottom 26x15 颜色 204/390——模板碎片化严重 + 暗底，TM_CCOEFF_NORMED 分数难以达到 0.8。实机：8-07 全天 0 confirmed（RyouToppa left2 4 次 + RealmRaid left3 ≥12 次），对比 8-06 曾有 66 confirmed——客户端渲染差异为高度可能叠加因素
- 根因：模板文件结构性缺陷（黑底+抗锯齿碎片+高阈值）为主；渲染差异待点击前后逐帧截图证实
- 最小修复建议：**颜色检测替代模板匹配**——Dokan 已有现成实现（`ex_green_mark.py:242-245` cv2.RGB2HSV + inRange lower/upper_green），下沉 GeneralBattle 确认流程
- 离线用例：构造绿标合成帧（含/不含 HSV 绿色标记）断言检测命中/拒绝
- 实机条件：单场带逐帧截图 + HSV 检测诊断日志
