## 二、逐条说明

### B1 Core CORS 收紧 — `app.py`

原 `allow_origins=["*"] + allow_credentials=True`：任何网页都能跨域调 `127.0.0.1:22267`
删配置、停脚本、触发 git pull。改为与 Bridge 一致的 localhost 正则放行
（`null` + `localhost/127.0.0.1/[::1]` 任意端口）。原生客户端（QML/OASX/Flutter）不是浏览器、
不受 CORS 约束；标注器页面由 Core 自身同源伺服——**不影响任何现有用法**。
`deploy.yaml` 的 `WebuiHost: 127.0.0.1` 请保持不变（改 0.0.0.0 会重新暴露）。

### C1 time_delta 天数解析 — `script_router.py`

```python
day = int(value[:2])   # 原 int(value[1]) 只取第二个字符，"10 06:00:00"→0，丢了十位
```
线格式是两位天数 `DD HH:MM:SS`，修复后可正确表达 00–99 天。
`value[3:]`（时分秒切片）不变，仍正确。

### C2 跨事件循环 WebSocket — 三文件协作

**问题**：`main_manager` 在独立线程的独立事件循环里跑推送协程，却直接向 uvicorn 主循环
accept 的 starlette WebSocket 调用 `send_json/send_text`。starlette 的 WebSocket 不是
跨循环安全的——这是偶发丢日志、偶发断连的根因（症状随时序漂移、难复现）。

**修法**（最小侵入，不动线程模型、不动 kill_server 语义）：
- `setting.py`：`State` 增加类属性 `main_loop`；
- `app.py` startup：`State.main_loop = asyncio.get_running_loop()` 记录主循环；
- `script_websocket.py`：新增 `_run_on_main()`——发送前若发现当前不在主循环，用
  `asyncio.run_coroutine_threadsafe` 把这次 send 定向回主循环执行；主循环未记录或已在
  主循环时，按原样直接执行（完全兼容）。`_send` 和 `_broadcast` 都走它。

**验证**（`handoff/patches/verify-ws-loop-safety.py`，可复跑）：构造主循环 + 工作线程独立循环，
用假连接记录 send 实际在哪个循环执行，断言跨循环发送被定向回主循环、数据无误，
并覆盖「同循环」「未记主循环」两条回退路径。沙箱 6/6 通过。

> 这条改的是上游核心并发结构，虽然专项测试证明了定向正确且不破坏原路径，
> 仍建议在你机器上真实 Core 长跑观察日志是否更稳。定位与修法都在本节，
> 若你或上游有更优方案（把推送整体搬进主循环），可替换本补丁。

### C4 可读性（无行为变化）

`script_router.py` 两个路由都叫 `script_task`，后者遮蔽前者——重命名为 `script_set_value`
（FastAPI 按装饰器注册，函数名不影响路由）。`main_manager.py` 的 `dict[str: ScriptProcess]`
是 `dict[slice]` 语法笔误，改成 `dict[str, ScriptProcess]`。

### 15 号未修项的处置

- **C2** 本轮已修（上表）。
- **C3**（`config_cache` 每次全量重建，性能根因）：Bridge 侧已用三级缓存绕开，不影响使用；
  上游真缓存属结构优化，留给上游。
- **C4 其余**（SSE 占位死端点、`task_delay` 死路径、pydantic `.dict()` 弃用、`os.kill(SIGILL)`）：
  均无实际使用影响或属死代码，改动风险大于收益，保持记录不动。

## 五、关于 A 级修复丢失（务必知晓）

本轮开工时从设备重新拉取 `module/server/` 发现：15 号交付的 A 级 `await` 修复
（REST 启停空操作、删除/重命名不停旧进程、重复启动双进程）**已不在设备上**，
文件回到了上游原版。最可能原因：期间对 OAS 仓库做过 `git pull`/`git checkout`/`git stash`
之类操作，把 `module/server/` 覆盖了。

**这正是「改上游代码」的固有风险**，也是为什么这些修复强烈建议走上游 PR：
- 本轮交付已把 A 级修复重新并入 `script_router.py`/`script_process.py`，覆盖一次即恢复；
- 但只要之后再 `git pull` 且上游未合入，就会再次丢失。根治办法是把
  `applied-03` 提成 PR 给 runhey/OnmyojiAutoScript，合入后本地永远无负担；
- 在此之前，每次同步上游后请重跑 `handoff/patches/verify-ws-loop-safety.py` 和
  `control-center/check-wiring.ps1`，确认修复仍在、三层仍通。

控制中心（`control-center/`）不受此影响——它是独立目录，不会被上游 git 操作触及。
