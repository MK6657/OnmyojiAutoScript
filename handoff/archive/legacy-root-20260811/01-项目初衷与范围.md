# 01 项目初衷与范围

## 项目初衷

原 OAS Core 的自动化任务能力已经比较完整，但原界面对普通使用者不够直观。此次二次开发的目标不是重写自动化逻辑，而是提供一个更容易理解和操作的控制中心：

- 使用中文任务名、配置名和说明，降低配置门槛；
- 每个账号拥有独立的任务开关、参数、状态和日志线程；
- 所有任务目录始终可见，点击任务即可查看配置，加号只负责启用；
- 已启用任务可停用、排序，并能保存为模板后跨账号复用；
- 日志只保留关键输出，避免日志面板挤占主要操作区域；
- 前端和原项目分开，便于未来同步 OAS 的功能和 Bug 修复。

## 本次交付范围

已实现的范围：

- React/Vite 中文前端；
- FastAPI Bridge；
- Electron portable 桌面版；
- 账号列表、账号创建和账号删除入口；
- 任务目录、启用/停用、当前账号任务排序；
- OAS Schema 通用配置表单；
- 配置模板保存、应用和删除；
- 每账号独立运行状态和 WebSocket 日志通道；
- Core、Bridge、前端的本地启动脚本；
- Bridge 的打包和健康检查脚本；
- 本交接文档和测试报告。

## 明确不在范围内的内容

- 不重写 OAS 的任务执行逻辑；
- 不自动替用户安装或启动游戏模拟器；
- 不把 OAS Core 内置进控制中心；
- 不把前端组件导入 `module/` 或 `tasks/`；
- 不在未确认配置和设备有效的情况下自动启动账号任务；
- 不把 Bridge 设计成公网服务。当前接口只面向本机使用，没有登录鉴权层。

## 验收标准

接手者判断功能是否正常时，至少应确认：

1. Core、Bridge、前端三层能独立启动；
2. 账号和 53 项任务目录能加载；
3. 点击未启用任务只查看配置，不改变启用状态；
4. 账号之间的任务和状态不会串线；
5. 配置保存仍通过 OAS Core；
6. 修改前端不需要改动 OAS Core 源码；
7. 桌面版可在没有 Vite 开发服务器的情况下打开前端；
8. 上游任务增加字段后，通用 Schema 渲染仍能显示，只有翻译映射需要补充时才补充。
