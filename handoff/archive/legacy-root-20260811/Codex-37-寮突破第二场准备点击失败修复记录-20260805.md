# Codex-37 寮突破第二场准备点击失败修复记录

日期：2026-08-05  
范围：`GeneralBattle` 通用战斗准备阶段；由寮突破 `RyouToppa` 第二场实机失败触发。  
分支：`codex/mk6657-secondary-development`

## 1. 现象

本轮寮突破已经完成预设准备、进入手动选择的目标寮，并成功完成第 1 个目标：

```text
RYOU_ATTACK_CONFIRM variant=I_FIRE_CURRENT
RYOU_BATTLE_START area=1
RYOU_BATTLE_RESULT area=1, result=success
RYOU_AREA_RESULT area=1, result=success
```

第 2 场已重新识别到寮突破“进攻”确认并进入通用战斗，但停在战斗准备页。程序连续两次认为准备按钮已点击，随后通用战斗返回失败：

```text
RYOU_BATTLE_START area=1
Current count: 2
Prepare button clicked (1/2)
Prepare button clicked (2/2)
Battle preparation was not confirmed; abort this battle safely
RYOU_BATTLE_RESULT area=1, result=failed
RYOU_AREA_RESULT area=1, result=battle_failed
RyouToppa task end: success=False, reason=battle_failed
```

错误快照：

`log/error/1785942337274/2026-08-05_23-05-37-251554.png`

快照显示游戏仍在“点击式神区域进行配置/准备”页面，右下角的蓝色“准备”按钮仍然可见，没有进入真实战斗，也没有误入友人帐。

## 2. 根因

通用准备按钮的旧点击链路使用 `RuleImage.coord()`：

```python
x, y = target.coord()
```

该方法会在模板命中的完整 `roi_front` 内随机取点。当前按钮模板命中区域约为 `100x100`，其中包含按钮外沿、透明装饰和非稳定可点击区域。实机第二场的点击记录为：

```text
Click (1253, 589) @ GB_PREPARE_HIGHLIGHT
Click (1176, 557) @ GB_PREPARE_HIGHLIGHT
```

这两个点不能证明命中了按钮有效中心。程序又只把“检测到模板且调用过 click”计为一次成功，没有在点击后确认按钮消失或真实战斗标记出现，因此两次无效点击后直接超时。

这不是寮突破目标选择、寮“进攻”按钮或窗口缩放导致的本轮根因。第 1 场使用相同通用流程成功，错误快照也确认页面仍为准备页。

## 3. 修复内容

修改文件：

- `tasks/Component/GeneralBattle/general_battle.py`
- `tasks/Component/GeneralBattle/tests/test_prepare_fallback.py`

处理方式：

- 新增 `C_PREPARE_SAFE`，使用 `1160..1214 x 585..639` 的按钮中心安全区，保留小范围随机性但排除模板外沿。
- 模板识别、窄 OCR、宽 OCR 和颜色兜底统一走安全区点击。
- 保留无设备测试夹具的旧回退路径，不改变识别契约。
- 准备点击上限从 `2` 次调整为 `3` 次。
- 真实战斗确认成功时增加 `GB_PREPARE_CONFIRMED state=real_battle_info/real_battle_friends` 日志。
- 不修改寮目标选择、绿标映射、票数判断和调度器。
