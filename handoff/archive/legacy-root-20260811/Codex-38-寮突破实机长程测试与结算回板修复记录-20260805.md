## 3. 已确认根因

### 3.1 结算页没有被消费

最后一场的控制流是：

```text
GeneralBattle: Battle result is win
GeneralBattle: Reconfirm the results of the battle
GeneralBattle: Click GB_WIN
GeneralBattle: Wait until appear GB_REWARD timeout
GeneralBattle: There is no reward, Exit battle
RyouToppa: RYOU_BOARD_RETURN_TIMEOUT
RyouToppa: RYOU_OUTCOME page_timeout
```

当客户端显示新版“点击屏幕继续”结算页时，没有独立的奖励面板。通用战斗在“无奖励”分支直接返回 `True`，但屏幕仍停留在结算页；寮突破随后只等待棋盘标志，25 秒后超时。人工在屏幕底部约 `(640,675)` 点击一次后，立即回到寮突破棋盘，证明不是战斗失败或模拟器失联。

这也是任务结束后 `GotoMain` 报 `Unknown ui page` 的直接前置原因：外层尝试回主界面时，游戏仍是结算页，而该页不在支持页面列表中。

### 3.2 启动瞬间的输入通道竞争

本轮启动最初出现一次：

```text
MinitouchOccupiedError: Timeout when connecting to minitouch, probably because another
Run script oas1 error
BrokenPipeError: [WinError 232]
```

随后第二次调度启动成功，连续完成 28 场。当前证据支持“前一个控制连接释放与第二次任务启动存在时序竞争”，还不能证明存在两个长期运行的业务任务；该问题单列为调度/设备生命周期缺陷，后续应增加启动互斥和退避重试。

