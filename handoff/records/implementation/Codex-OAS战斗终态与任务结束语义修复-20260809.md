# OAS 战斗终态与任务结束语义修复实施记录

日期：2026-08-09

## 结论

战斗终态、绿标结果、任务结束和失败调度已改为结构化语义。离线回归与正式服务启停链路通过；这份记录不代表 RealmRaid 绿标或战斗长程实机结案。

## 实现

- 新增 `BattleOutcome`：`not_started`、`active_unconfirmed`、`victory`、`defeat`、`settling`、`returned`、`aborted`。
- `GotoMain` 在 `page_battle` 保持门禁，活动战斗未交出明确终态前不把“继续”当普通导航按钮。
- `TaskEnd` 统一携带 `outcome`、`success`、`reason`、`statistics` 和 `next_run`；项目内隐式 `TaskEnd` 路径已迁移为显式结果。
- 新增 `GreenMarkResult`：`confirmed`、`unconfirmed`、`skipped`、`terminal`，并记录目标、点击点、检测点、检测器、最高分、帧哈希、尝试次数和原因。
- 绿标未确认只表示增益优化失败，默认不阻断正常战斗；进入结算或终态时返回 `terminal`，由战斗状态机接管。
- 任务失败统一写入带 `caller` 和 `reason` 的 `SCHEDULE_DECISION`，可恢复异常先按失败间隔推迟，避免旧 `next_run` 立即重启同一失败任务。
- 调度默认只允许调用者修改自身任务；探索、斗技、活动监控、Restart、控制中心、组队同步和共享 WantedQuests 使用显式白名单，未授权跨任务写入在保存前抛错。
- `task_call` 已改走同一 `schedule` 门禁，不再直接写 `next_run` 绕过审计。
