# RY-GUILD 排序验证与固定首卡选择修复

日期：2026-08-11

## 结论

寮突破的自动选寮已改为适配当前游戏界面的排序协议：右侧“勋章奖励”按钮控制整个列表的升序/降序，程序不再尝试识别地图上所有寮，也不再在未验证排序时固定点击第一张。

程序现在先读取右侧四行勋章数，切换排序并比较两端，再恢复到已验证的降序页。只有最终降序页与先前记录完全一致，才点击固定第一行并验证进入寮突破棋盘。任一 OCR 缺失、非单调、排序未变化、恢复值不一致或页面转换失败都会停止，不点击寮卡。

## 实现

- `GuildSortSnapshot` 保存一帧中四行候选、排序方向、数值和帧身份。
- `classify_guild_sort_order()` 只接受完整且单调的四行数值；混乱顺序直接拒绝。
- `compare_guild_sort_snapshots()` 要求两次观察方向相反，并记录全局最高值和最低值。
- 初始页为降序时执行“降序 -> 升序 -> 降序”；初始页为升序时执行“升序 -> 降序”。
- `verify_final_descending_snapshot()` 要求最终降序值与此前记录逐项一致，防止列表在验证期间刷新或换批。
- 点击日志明确记录 `candidate=row_1`、实际 `medal_reward` 和 `verified_sort=descending`；“已点击”和“已验证最高”不再混写。
- 当前生产 OCR 区域对应右侧可见四行勋章数字；布局、分辨率或行数变化时应 fail-closed 并重新标定。

## 阵容锁定边界

本轮同时修正了寮突破阵容锁定的状态语义：画面显示的是“可执行动作”图标，而不是简单的当前状态标志。程序需要连续两帧确认“锁定动作可用”，点击一次后再连续两帧确认“解锁动作可用”，才能证明视觉锁定切换完成。

实机证明当前寮突破即使视觉锁定已经切换成功，后续战斗仍可能持续出现准备页。因此新增 `VERIFIED_PREPARE_REQUIRED`：不重复点击锁定，保留有限准备兜底，并把该现象记录为当前客户端/副本边界，而不是伪造“锁定直入成功”或无限重试。

- “勋章奖励”不再切换全局排序。
