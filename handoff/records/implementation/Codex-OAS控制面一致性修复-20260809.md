## 生命周期

- 每个账号使用跨线程 `RLock`，覆盖 REST、WebSocket、自动启动与独立监控线程。
- 子进程对象只在 `process.start()` 成功后发布，监控无法回收未启动对象。
- 每次运行创建独立 state queue 和 log pipe，停止、异常退出和启动失败时统一关闭。
- start/stop/reap 不在持有锁时执行异步广播，避免跨事件循环锁问题。
- 25 轮双入口并发启动/停止测试中，同一账号存活 child 始终不超过一个。

## 命令回执

- Bridge 发送 `{command_id, command}`，Core 先回 `accepted`，执行后回 `completed` 或 `failed`。
- 最终回执包含 success、changed、state、run_id 或失败原因。
- Bridge 等待最终回执后才返回 `accepted=true,status=completed`。
- WebSocket 超时/断线清理 pending command；Core 明确执行失败时不会被 socket send 成功掩盖。
- REST 兜底也必须返回结构化完成回执，缺失回执或 success=false 映射为 502。

## 配置事务

- 新增单次批量 PATCH 和文件 SHA-256 revision。
- 整个请求在同一文件锁内读取、校验 revision、应用全部字段、Pydantic 校验并原子替换。
- 任一字段错误不写文件；旧 revision 返回 409。
- 合法的新模型叶子字段可在旧 JSON 中补入，但必须先通过模型字段校验。
- worker 的旧 `ConfigModel` 保存时只把相对 baseline 真正改变的叶子合并到最新文件，保留 UI 已修改的无关字段。
