# 测试与结案规范

## 文档类型

| 类型 | 内容 | 是否代表结案 |
|---|---|---|
| 实测记录 | 前置、动作、截图、日志、结果和根因 | 否 |
| 实施记录 | 改动文件、离线测试、回滚点和未实测风险 | 否 |
| 审计报告 | 只读复核、证据裁定和建议 | 否 |
| 结案记录 | 验收环境、离线结果、实机结果和剩余风险 | 是 |

> 结案记录存放于 handoff/records/closure/，命名 Codex-结案-<事项ID>-<日期>.md。**口头结案无效**：总表或任务文件中标注「已结案」之前，必须先存在对应 closure 文件（DeepSeek-13 4.7 修订）。结案记录由当轮执行代理在验收通过后创建，内容须含：范围限定、验收环境、离线结果、真实证据、长程结果、剩余风险与重新打开条件。

## 记录要求

- 每次实测使用不可变文件，不覆盖旧记录。
- 实测记录文件末尾必须包含「当前状态：未结案/部分通过」一行（DeepSeek-13 4.11 修订）。
- 截图必须注明时间、事项 ID、场景、前后状态和分辨率。
- 日志引用必须包含文件名、关键时间或行号。
- “代码已实施”不能写成“功能已完成”。
- 没有真实游戏证据的项目状态只能是 待实测 或 部分通过。
- 发现新证据时重新打开原事项 ID，不另起重复事项。
- 坐标候选必须记录源帧 SHA-256、画布规格、mapping revision、标注版本和验证结果；视觉描边、编号徽章、缩放和黑白模式不属于业务几何。
- 跨项目证据优先使用 `handoff/contracts/v1` 的 `DeviceIdentity`、`FrameEnvelope`、`CandidateEnvelope` 和 `EvidenceManifest`；契约存在不等于候选已应用。

## 停止扩大量条件

出现错误坐标、友人帐、桌面切换、奖励误判、票数不一致、自动战斗失效、GameStuck、重复任务实例或异常回主界面时，立即停止长程测试。

处理顺序：

1. 保存最后稳定截图、现场截图、日志和配置快照。
2. 区分识别、坐标、状态机、调度和游戏语义根因。
3. 做最小修复并补离线测试。
4. 重跑同一阶段，再决定是否扩大范围。
