# 11 故障排查

## 页面显示“Core 未连接”

先检查 Core：

```powershell
Invoke-RestMethod http://127.0.0.1:22267/test
```

如果失败，先启动原 OAS Core。若 Core 使用其他端口，用同样的 Core URL 启动 Bridge：

```powershell
.\control-center\launcher\start-bridge.ps1 -CoreUrl http://127.0.0.1:22270
```

## 页面显示“等待 Bridge”或任务为空

检查：

```powershell
Invoke-RestMethod http://127.0.0.1:22367/api/v1/health
```

如果失败，启动：

```powershell
.\control-center\launcher\start-bridge.ps1
```

开发模式页面必须从 `http://127.0.0.1:5173` 打开，而不是直接打开 `frontend/dist/index.html`，这样 `/api` proxy 和 WebSocket 才会正确工作。

## Bridge 启动时报缺少模块

使用项目解释器安装：

```powershell
.\.venv\Scripts\python.exe -m pip install -r .\control-center\bridge\requirements.txt
```

脚本已优先寻找根目录 `.venv`；如果接手者使用独立的 Bridge 虚拟环境，则安装到 `control-center\bridge\.venv`。

## 任务目录有中文，但配置字段仍显示英文

检查 `control-center/frontend/src/locale.js`：

1. 添加字段的 `fieldLabels`；
2. 添加字段说明的 `descriptions`；
3. 添加 enum 的 `optionLabels`；
4. 检查 `normalizeKey` 和 `canonicalKey` 是否能覆盖 Core 的 key 写法；
5. 不要修改 Core 返回的字段名。

协议名、设备包名、模型名、URL 和内部 ID 保留英文是设计行为。

## 配置保存失败

检查：

- Core 是否仍在线；
- 当前账号和任务是否正确；
- 日期/时间值是否符合 Core Schema；
- 是否把只读字段或不支持的类型提交给 Core；
- Bridge 返回的 HTTP 状态和 `detail`。

不要直接编辑 `config/*.json` 规避错误，先保留原始响应以便定位 Schema 变化。

## 桌面版打不开

检查程序旁的资源是否完整，重新执行：

```powershell
Set-Location D:\OSAyys\control-center\desktop
.\build.ps1
```

如果构建报 PyInstaller 缺失：

```powershell
python -m pip install pyinstaller
```

如果程序打开但没有数据，确认 Core 已运行，并确认没有被其他程序占用 22367。桌面版默认会连接 `127.0.0.1:22267`，不会替你启动 Core。

## 端口冲突

```powershell
Get-NetTCPConnection -State Listen | Where-Object { $_.LocalPort -in 22267,22367,5173 } |
  Select-Object LocalAddress,LocalPort,OwningProcess
```

不要随意结束未知进程。先根据 PID、命令行和启动时间确认它是本项目的 Core、Bridge 或 Vite。

## 中文乱码

源码文件按 UTF-8 保存。Windows PowerShell 旧版本用 `Get-Content -Encoding UTF8` 查看，不要根据未指定编码的终端输出判断源码是否乱码。界面浏览器和 Electron 应以实际渲染结果为准。
