## 1. 前端加固（`desktop/release/UI-claude/src/App.jsx` + `api.js`）

审计方法：3 个子代理分别做「前端↔Bridge 契约」「入口 / 打包」「文档 / 架构」只读审计，逐条给出
file:line + 根因 + 补丁；下面每条都已落地并经真实编译（esbuild 打包 `src/main.jsx` 通过）验证。

| 编号 | 级别 | 现象（用户视角） | 根因 | 修法 |
|---|---|---|---|---|
| 模板哨兵 | 中 | 换到没有 `/templates` 的旧 Bridge 时，存的模板刷新即丢 | `api.templates()` 用 `asList(null)` 把「接口缺失」哨兵塌成 `[]`，`loadTemplates` 据此把存储误判为 bridge，`persistTemplates` 便不再落本地 | `api.js`：`templates()` 保留 `null` 哨兵，只有真拿到响应才 `asList` |
| 调度清空 | 中 | 启用 / 停用 / 保存 / 收到指令后，概览「任务调度」被清空 | 三处二次刷新 `api.schedule(id).then(setSchedule)`，接口缺失 / 瞬时返回 `null` 时直接把面板写没 | 三处改 `.then((s) => { if (s) setSchedule(s) })` |
| F1 | 高 | **先开界面、后开 Core**：Core 起来后界面仍卡在红色错误横幅 + 空账号 / 空任务，必须手动刷新 | 启动那次 `accounts/catalog` 拉取失败后没有任何自愈路径；`bridge.ready` 只补账号不补目录 / 不清横幅 | 健康轮询在 Bridge+Core 恢复且当时出过错时补拉 `accounts/catalog` 并清 `bootError`；`bridge.ready` 补拉 catalog |
| F6 | 低 | Bridge 进程死掉后，界面仍显示「Core 在线」，启动前检查还是绿的 | 轮询 catch 只把 `bridge` 置 offline，`core` 仍是 `ok` | catch 同时把 `core` 置 offline |
| F2 | 中 | 一号启动后立刻切到二号，二号概览 / 开关串成一号的数据 | runAction / toggleTask / saveConfig 的二次刷新用了闭包里旧的 `selectedId`，无账号守卫 | 捕获 `accountId`，写状态前加 `selectedIdRef.current === accountId` 守卫 |
| F4 | 中 | 开关写成功，但随后的刷新失败被当成「操作失败」，开关不动，诱导用户重复点把状态点反 | `setTaskEnabled` 与后续 `accountTasks` 刷新共用一个 try/catch | 拆开：只有「写开关」失败才算失败；刷新是尽力而为，失败不盖掉成功提示 |
| F5 | 低 | 网络抖动时 `POST /accounts`、`/actions` 被自动重发，触发「已存在」误报或重复动作 | `request()` 对所有方法都重试 | 只对幂等方法（GET/PUT/DELETE）自动重试，POST 不重试 |
| F7 | 低 | 双窗口下，一个窗口新建账号，另一个窗口不刷新（删除却会刷新，不对称） | 只处理了 `account.deleted`，漏了 `account.created` | 加 `account.created` → `refreshAccounts()` |
| 删账号 | 高 | **设置页点「删除 {账号}」删不掉**，请求打到 `/accounts/undefined`(404) —— 正是原始反馈「账号没法删除」 | 上一轮把 `deleteAccount`/`renameAccount` 改成默认参数 `(target = account)` 后，SettingsView 用 `onClick={onDeleteAccount}` 把**点击事件**当成了 target，`target.id` 为 undefined | App.jsx 传参改 `onDeleteAccount={() => deleteAccount(account)}`、`onRenameAccount={() => renameAccount(account)}`；侧栏 ⋯ 菜单本就显式传 `item`，一直正常 |

> 未处理（留记录）：F8 task-order 前端无调用点（Bridge / DB / mock 都支持，属预留能力，非 bug），保持现状。
> 「删账号」这条是上一轮重构埋下的，本轮由 e2e 回归先跑出 20/21 才抓到——留作“改默认参数要顺带查所有调用点”的教训。
> 代码里每条修复都带 `handoff/17 Fx` 注释，便于日后定位。
