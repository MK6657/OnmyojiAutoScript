# 交接 19 · 「连不上模拟器」根因与修复（adb 缺失）

> 现象：新界面一切正常、`Core 在线`、实时通道已连接，但账号 `teat2` 跑任务后变「异常」、`test1` 顶部一直「设备信息读取中」，
> 启动任何任务都控制不了游戏。用户以为是设置不对或链路不通。

日期：2026-07-27（用户机时区）。

## 1. 根因（看日志实锤，不是猜）

`log/2026-07-27_teat2.txt` 的 traceback：

```
module/device/connection.py:724  list_device → self.adb_client._connect()
adbutils/__init__.py:105  _safe_connect →
    subprocess.run([adb_path(), "start-server"], timeout=20)   # adb_path() 返回了裸 'adb'
args = ['adb', 'start-server']
FileNotFoundError: [WinError 2] 系统找不到指定的文件。
ERROR | Error: 1
```

- OAS 连模拟器要经过 **ADB**。它先连本地 adb server(127.0.0.1:5037)，连不上就自动 `adb start-server`，
  但这里调的是**裸 `adb`**，而系统 PATH 里没有 adb → `FileNotFoundError` → 崩在设备层 → 连不上任何模拟器。
- 讽刺的是 **adb 其实就在项目里**：`.venv\Lib\site-packages\adbutils\binaries\adb.exe`（2.6MB，确认存在），
  只是没进 PATH，adb server 也没起来。
- `bin\` 下只有 droidcast/hermit/scrcpy，没有 adb。

## 2. 定位结论：是「链路」不是「界面设置」，也不是 Bridge

| 层 | 状态 |
|---|---|
| 界面 ↔ Bridge | 正常（页面能加载账号/任务/日志） |
| Bridge ↔ Core | 正常（`Core 在线` = Bridge 能连 Core `/test`） |
| **Core ↔ 模拟器（ADB）** | **断**（adb 找不到，server 没起）← 问题在这 |

所以 `test1` 的「设备信息读取中」也是同一根因的连带表现：读运行设置里的设备段时，Core 在设备连接环节就崩了。

## 3. 修复（纯 launcher，不动上游 Core）

`control-center\start.ps1` 新增 `Initialize-Adb`，在启动 Core 之前：

1. 把 `.venv\Lib\site-packages\adbutils\binaries` 加进本进程 PATH（新拉起的 Core 会继承，自己也能找到 adb）；
2. 预先 `adb start-server`（即便 Core 是复用的，server 已就绪，它下次连设备也不会再崩——连的是现成的 server）。

选择改 launcher 而不是 Core：`git pull` 不受影响；根治办法仍是把 adb 路径处理提给上游。

## 4. 用户要做什么

1. **关掉旧的「OAS Core」窗口**（它是没 adb 时启动的，PATH 里没有 adb，必须重启才能生效）；
2. 双击 `启动.bat` → start.ps1 会先「[0/3] adb 已加入 PATH 并启动 adb server」，再拉起 Core；
3. 打开模拟器和游戏 → 概览「🔗 扫描并绑定窗口」绑定，或到「运行设置 → 设备」把 `serial` 设为模拟器 ADB 地址；
4. 启用任务 → 启动。

## 5. 仍需注意（adb 起来之后）

adb server 起来只是「能用 adb 了」。还要让**模拟器被 adb 识别**：
- MuMu12 单开 ADB 地址通常 `127.0.0.1:16384`（`#0` 实例）；多开每个 +32。
- 若 `serial=auto` 仍找不到，手动在「运行设置 → 设备」把 `serial` 设成上面的地址，或先 `adb connect 127.0.0.1:16384`。
- 验证：重启 Core 后，`.venv\...\adbutils\binaries\adb.exe devices` 应能列出模拟器设备。

## 6. 备注：窗口句柄 vs serial

前一轮做的「扫描绑定窗口」写的是 `device.handle`，用于多开时定位具体窗口；但 OAS 的截图/控制默认走 ADB(minitouch)，
**真正的传输还是 serial(ADB)**。所以 adb 通 + serial 对，才是能跑起来的关键；handle 是锦上添花。
