# 06 前端二次开发指南

## 开发命令

```powershell
Set-Location D:\OSAyys\control-center\frontend
npm install
npm run dev -- --host 127.0.0.1 --port 5173
npm run build
```

桌面生产构建由 `D:\OSAyys\control-center\desktop\build.ps1` 统一执行，不要手工把 `dist` 拷到桌面目录后忘记重新打包。

## 主要文件

### `src/App.jsx`

主工作区和交互逻辑，包括：账号加载、任务目录、任务启用/停用、排序、配置读取/保存、模板和 WebSocket 事件。

### `src/locale.js`

中文映射层，包括：

- 任务 ID → 中文任务名；
- 分组 key → 中文分组名；
- 字段名/字段标题 → 中文字段名；
- 字段说明 key → 中文说明；
- enum 选项 → 中文选项；
- 通用英文 key 的分词 fallback。

内部任务 ID 和协议名仍保留在“内部标识”或选项中，方便和 OAS 上游代码对照。

### `src/styles.css`

四栏工作区布局：全部任务、当前账号任务、任务设置、关键日志。每栏可独立滚动，页面本身保留窄窗口下的可滚动能力。

## 前端数据边界

前端只调用：

```text
${VITE_BRIDGE_URL}/api/v1
```

开发模式未指定 `VITE_BRIDGE_URL` 时，使用当前 Vite 地址并通过 proxy 转发；桌面构建通过 `.env.desktop`/构建脚本固定到 `http://127.0.0.1:22367`。

本地浏览器存储键：

```text
oas-control-center.templates.v1
oas-control-center.task-order.v1
```

模板和任务显示排序只是 UI 数据，不能代替 Core 的实际任务配置。

## 新增任务字段的处理顺序

1. 先让 Bridge 的通用 `ConfigField` 继续传递字段类型、默认值、当前值和选项；
2. 在前端确认通用控件能否正确渲染；
3. 再在 `locale.js` 添加字段名、说明和选项翻译；
4. 仅当字段类型或 Core 接口协议变化时，才调整 Bridge；
5. 给新增字段补一项只读配置接口测试和中文化扫描。

## 不要做的事情

- 不在 `App.jsx` 中硬编码账号配置值；
- 不从前端直接读取 `config/*.json`；
- 不把 `tasks` 的 Python 类名复制到前端作为业务逻辑；
- 不为了翻译而修改 Core 返回的内部 ID；
- 不把模板保存直接伪装成 Core 保存；
- 不在没有确认目标账号的情况下调用启动、停止、删除接口。

## UI 体验回归重点

每次改动后检查：

- 点击任务名称是否只查看配置；
- `＋` 是否只改变当前账号的启用状态；
- 当前任务的排序和停用按钮是否可见；
- 配置面板和任务目录是否都有滚动条；
- 小窗口下日志是否仍然只占较小区域；
- 配置字段是否中文，技术协议名是否保持可识别；
- 不同账号切换时任务、配置和日志是否跟随账号刷新。
