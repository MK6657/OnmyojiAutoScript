# 权属、署名与许可证档案

本目录是 MK6657 本地二次开发项目关于处置授权、历史来源、贡献者署名和第三方许可证的统一档案入口。

## 当前项目口径

- MK6657 已明确确认：上游作者团体已通过群聊和电话授予其对本地项目进行使用、修改、二次或三次开发、内部使用、商业化和许可证处置的完整权限。
- 自 2026-08-03 起，本地项目的产品方向、维护、发布和二次开发决策由 MK6657 负责。
- 上游项目长期未维护，上游代码在本项目中作为历史基础和可复用实现；实际业务流程以 MK6657 的实测、反馈和最终确认作为准则。
- 上述项目授权不自动替代从其他独立项目引入代码所附带的许可证。第三方来源按 `THIRD-PARTY-NOTICES.md` 单独管理。

## 文件索引

- `PROJECT-AUTHORITY.md`：项目处置授权与本地二开责任记录。
- `UPSTREAM-ATTRIBUTION.md`：上游来源、历史基线、当前仓库和署名原则。
- `UPSTREAM-CONTRIBUTORS.txt`：从完整 Git 历史提取的贡献者显示名快照。
- `THIRD-PARTY-NOTICES.md`：第三方复制代码、依赖和待核实来源清单。
- `LICENSE-CUTOVER-CHECKLIST.md`：未来从当前根许可证切换到正式项目许可证时的操作清单。
- `licenses/`：当前及第三方许可证原文快照。

## 当前状态

本轮只完成归档和管理口径统一，不改变任何业务代码，也不构成一次许可证切换。仓库根目录现有 `LICENSE` 和 `README.md` 中的 GPLv3 声明继续有效，直到 MK6657 明确选择新许可证，并在独立的许可证切换提交中同步修改根许可证、README、安装包声明和第三方通知。

源码内已有作者注释暂不批量删除。后续若统一源码头部，必须先保留本目录的历史来源记录，并避免删除第三方许可证要求保留的版权和许可声明。

## 维护规则

1. 新增复制或改写自外部项目的代码时，同时更新 `THIRD-PARTY-NOTICES.md`。
2. 上游同步、许可口径或项目负责人发生变化时，同时更新 `PROJECT-AUTHORITY.md` 和 `UPSTREAM-ATTRIBUTION.md`。
3. 发布包必须携带与该版本一致的第三方通知；不得从开发机临时目录拼接通知。
4. 群聊截图、录音、电话号码和成员真实身份等授权原始证据由 MK6657 离线保管，不提交到代码仓库。
5. 本目录记录工程管理事实与来源，不替代针对具体发行地区和合同文本的专业法律意见。
